Blank vouchers, for when the generator is not available

These are ordinary DMU Food & Drink vouchers with the parts that change between batches left as ruled lines. They are here so a print run is still possible when the voucher generator, or the computer it runs on, is not.

Print these now, not on the day

The generator is what produced this pad, so it cannot produce one once it has stopped working. Print it while everything is working and keep the paper somewhere findable. A pad in a drawer is the only version of this that is any use.

Filling one in

Three things are written by hand on each voucher:

  • Value. The amount from the approved request, in the box beside the pound sign.
  • Valid until. The expiry date from the request. The vendor sheet tells vendors to refuse an expired voucher, so a voucher with this left empty is one nobody can safely accept.
  • Voucher code. The request's ID from the approval export, then the ticket number, exactly as the generator would print it. Request 12 issuing 40 vouchers is 12-01 through 12-40. Every voucher gets its own.

Write down what you issue

A run made from this pad produces no batch summary. The generator normally writes a file listing every code and its value, and that file is what reconciling against the vendor's returns depends on. Made by hand, the only record is the one somebody makes, so keep a list of the codes used, the value, and which request they were for, and file it where the batch folder would have gone.

Two things to be careful about

  • A written value can be altered in a way a printed one cannot. Store this pad like chequebook stock rather than like stationery, and write the value clearly enough that a changed one would show.
  • No code may be used twice. The generator cannot repeat one; a person can. Cross each code off the list as it is written.
